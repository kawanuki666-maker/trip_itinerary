# 晋北行程 · CMS 后台管理系统设计

**版本：** 3.0
**日期：** 2026-05-21
**状态：** 已确认

---

## 1. 背景与目标

### 1.1 现状
- `index.html` 为单页静态网页，所有数据（行程、景点、实用信息）硬编码在 JS 数组中
- 无后端、无数据库，数据修改需直接改代码
- 无图片管理、无点评系统

### 1.2 目标
将项目升级为轻量级 CMS，支持：
- 所有行程数据（景点、住宿、实用信息）通过后台管理
- 景点照片上传、点评撰写、五星评分
- 一键发布到 GitHub Pages
- 保持纯前端架构，无需自建服务器
- **支持多套行程管理**（预留扩展能力）

### 1.3 使用场景
- **个人记录**：旅行前规划 / 旅行中查看 / 旅行后整理
- **分享型页面**：旅行后发布到 GitHub Pages 分享给朋友

### 2.3 数据流向

1. 用户在本地打开 `admin.html`
2. 编辑景点、行程、照片、点评
3. 点"保存" → GitHub REST API 提交到私有分支
4. GitHub Actions 检测到更新 → 自动部署到 GitHub Pages
5. 几秒后线上生效

## 3. 数据结构

### 3.1 顶层结构（支持多行程）

```json
{
  "currentTrip": "jinbei_2026",
  "trips": {
    "jinbei_2026": { ... }
  }
}
```

> **多行程扩展**：未来添加新行程，只需在 `trips` 下新增一个 key-value 对，`currentTrip` 指向当前展示的行程。Admin 后台支持切换行程。首页展示哪个行程由 `currentTrip` 控制。

### 3.2 各模块结构

#### 3.2.1 trip（行程基本信息）

```json
"trip": {
  "id": "jinbei_2026",
  "title": "晋北八日",
  "dates": "2026.6.13 — 6.20",
  "subtitle": "穿越千年的建筑艺术巡礼",
  "description": "从云冈石窟的北魏造像，到应县木塔的千年木构；\n从悬空寺的悬崖奇迹，到五台山的佛国净土——\n这是一场跨越时空的文明对话。"
}
```

> **统计数字（动态计算，不存储）**：
> - `days`：每日行程数组长度
> - `cities`：所有景点中不重复的城市数（从景点 `city` 字段统计）
> - `sites`：所有景点的总数（`spots` 数组长度）
> - `mustBook`：需要预约的景点数（`spots` 中 `needReservation: true` 的数量）

#### 3.2.2 platforms（购票平台）

```json
"platforms": [
  {
    "id": "p1",
    "name": "大同旅游景区直通车",
    "use": "大同↔云冈石窟 / 应县木塔 / 悬空寺"
  }
]
```

#### 3.2.3 reservations（预约提醒）

```json
"reservations": [
  {
    "id": "r1",
    "spotId": "spot_1",
    "platform": "云冈研究院/云冈文旅小程序",
    "advance": "提前7天",
    "dueDate": "6月7日"
  }
]
```

> **设计原则**：预约提醒通过 `spotId` 关联景点，详细的预约信息（平台、提前天数、截止日期）集中管理。景点库中只保留 `needReservation: true/false` 布尔值，无需存储详细文字。

#### 3.2.4 spots（景点库）

```json
"spots": [
  {
    "id": "spot_1",
    "name": "云冈石窟",
    "city": "大同",
    "brief": "北魏皇家石窟、昙曜五窟、第20窟露天大佛",
    "hours": "8:00-17:30",
    "ticket": "120元",
    "needReservation": true,
    "description": "云冈石窟是中国四大石窟之一，始建于北魏和平元年（公元460年），由高僧昙曜主持开凿...",
    "photos": ["photo_001.jpg", "photo_002.jpg"],
    "review": "非常震撼！北魏艺术的巅峰之作。",
    "rating": 4.5
  }
]
```

> **景点与天数的关联方式**：通过 ID 引用。移动景点（如从第1天移到第2天）只需修改 `spotIds` 数组，景点库中的数据（照片、点评、评分）保持不变。
>
> **城市字段**：`city` 字段用于统计"去了几座城市"，同时支持按城市筛选景点。

#### 3.2.5 days（每日行程）

```json
"days": [
  {
    "id": "day1",
    "day": 1,
    "date": "6.13",
    "weekday": "周五",
    "title": "抵达大同 · 古城夜景",
    "theme": "古城初探",
    "transport": "上海→大同：HO1065 (07:15-10:05)",
    "warning": null,
    "accommodation": {
      "name": "大同永泰广场漫心酒店",
      "location": "大同市平城区永泰南路与迎宾街交汇处",
      "photo": "hotel_day1.jpg"
    },
    "spotIds": ["spot_1", "spot_2", "spot_3"]
  }
]
```

> **景点顺序**：`spotIds` 数组的顺序即为当天的游览顺序。

#### 3.2.6 照片存储

- 照片文件存储在 `photos/` 目录
- 景点照片：`photos/spots/spot_1_001.jpg`
- 住宿照片：`photos/hotels/hotel_day1.jpg`

## 4. Admin 后台功能规划

### 4.1 模块一：基础信息管理

| 功能 | 说明 |
|---|---|
| 行程基本信息 | 编辑标题、日期、副标题、描述 |
| 平台管理 | CRUD 购票平台（名称、用途） |
| 预约提醒管理 | 勾选需要预约的景点（自动过滤 `needReservation: true` 的景点）+ 填写预约详情 |

### 4.2 模块二：景点库管理

| 功能 | 说明 |
|---|---|
| 景点列表 | 全局景点库，可按城市筛选 |
| 基础信息编辑 | 名称、城市、简要描述 |
| 详细信息编辑 | 开放时间、门票、是否需要预约 |
| 景点介绍编辑 | 多行文本描述 |
| 照片上传 | 支持多张，自动压缩（≤500KB） |
| 点评管理 | 文字点评（≤200字）+ 五星评分（支持半星） |

### 4.3 模块三：每日行程管理

| 功能 | 说明 |
|---|---|
| 行程列表 | 按天展示，可折叠/展开 |
| 基础信息编辑 | 标题、日期、星期、主题 |
| 交通信息编辑 | 文本编辑 |
| 警告信息编辑 | 文本编辑（非必填） |
| 住宿管理 | 酒店名称 / 位置 / 上传照片（非必填） |
| 景点安排 | 从景点库选择景点添加到当天，调整游览顺序（拖拽排序） |

> **景点安排交互**：从景点库列表中选择景点，点击"添加到当天"；当天已添加的景点可拖拽调整顺序，或移除（移回库中，不丢失数据）。

### 4.4 模块四：通用功能

| 功能 | 说明 |
|---|---|
| 图片管理 | 查看已上传图片，删除不需要的 |
| 数据预览 | 实时预览完整 JSON |
| 保存 & 发布 | 保存到 GitHub 私有分支，自动触发 GitHub Actions 部署 |

### 4.5 Admin 页面结构

```
/ (登录页)
 └── 输入密码 + GitHub Token → 进入管理后台
/admin (主后台)
 ├── 侧边导航
 │   ├── 基础信息
 │   ├── 景点库
 │   ├── 每日行程
 │   └── 图片管理
 └── 主内容区（根据导航切换）
```

## 5. 前台交互（需同步实现）

### 5.1 住宿详情卡片

**触发方式**：点击每日行程弹窗中的住宿名称

**卡片内容**：
- 酒店名称（标题）
- 酒店位置（文字）
- 酒店照片（1张，可选）

**卡片样式**：与现有弹窗风格一致（直角、深色背景、琥珀金点缀）

### 5.2 景点照片展示

- 景点详情弹窗中，如果有照片，显示照片缩略图
- 点击照片可放大查看

### 5.3 景点评分展示

- 五星制，支持半星
- 无评分时显示为空

### 5.4 行程弹窗中的景点顺序

- 景点按 `spotIds` 顺序展示，体现当天游览路线

## 6. 技术方案

### 6.1 技术选型

| 组件 | 选择 | 理由 |
|---|---|---|
| Admin 框架 | 原生 HTML/CSS/JS | 零依赖，与现有项目一致 |
| 数据存储 | `data/itinerary.json` | 人类可读，方便版本管理 |
| GitHub 交互 | GitHub REST API | 无需后端，纯浏览器操作 |
| 图片压缩 | 浏览器 Canvas API | 避免超过 GitHub 100MB 单文件限制 |
| 自动发布 | GitHub Actions | push 后自动部署到 GitHub Pages |
| Token 存储 | 浏览器 sessionStorage | 仅当前会话有效，关闭浏览器即清除 |

### 6.2 安全机制

| 措施 | 说明 |
|---|---|
| Admin 独立密码 | 非 GitHub 账号密码，独立设置 |
| Token 本地存储 | GitHub Personal Access Token 仅存于浏览器 |
| 私有分支 | admin.html 和 Token 配置不提交到公开仓库 |
| 页面保护 | admin.html 首次访问需输入密码 + Token |

### 6.3 GitHub Actions 部署流程

1. 用户在 admin 保存 → 数据提交到私有分支
2. 私有分支 push 触发 Actions workflow
3. Actions 自动将数据合并到公开分支
4. GitHub Pages 自动从公开分支发布

## 8. 已知约束

1. **GitHub 单文件 100MB 限制**：图片通过 Canvas 压缩至 ≤500KB
2. **GitHub 仓库建议 <1GB**：照片过多时需定期清理或考虑图床
3. **纯前端限制**：所有逻辑在浏览器运行，无法实现复杂权限管理
4. **Token 有效期**：GitHub PAT 默认无过期，但建议定期更新
