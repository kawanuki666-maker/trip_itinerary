## P1 · 智能一键导入 ✅ 已完成

### 功能特性
- JSON 导入，自动按依赖顺序处理（区域 → 景点/酒店 → 行程）
- 导入文件**无需维护任何 ID**，系统自动生成并匹配引用关系
- 自动识别新增数据，避免重复（去重依据：景点按名称+城市，酒店按名称+位置，行程按标题）
- 支持**增量导入**（推荐，仅新增不存在的数据）和**全量覆盖**两种模式
- 导入前预览：显示各类型数据的新增/已存在数量

### 导入文件格式（无 ID 模板）

```json
{
  "locations": { "国内": { "省份名": { "城市名": ["区县名"] } } },
  "spots": [
    {
      "name": "景点名称",
      "city": "省份 - 城市 - 区县",
      "brief": "简介",
      "hours": "开放时间",
      "ticket": "门票",
      "needReservation": false,
      "description": "详细介绍"
    }
  ],
  "hotels": [
    {
      "name": "酒店名称",
      "location": "省份 - 城市 - 区县",
      "address": "地址",
      "phone": "电话",
      "checkInTime": "14:00",
      "checkOutTime": "12:00",
      "notes": "备注"
    }
  ],
  "trips": [
    {
      "title": "行程标题",
      "startDate": "2026-01-01",
      "endDate": "2026-01-03",
      "subtitle": "副标题",
      "description": "行程描述",
      "days": [
        {
          "day": 1,
          "title": "第1天标题",
          "theme": "主题",
          "spots": ["景点名称1", "景点名称2"],
          "accommodation": "酒店名称",
          "transport": "交通说明",
          "note": "备注"
        }
      ],
      "platforms": [
        { "name": "平台名称", "uses": ["用途1", "用途2"] }
      ],
      "reservations": [
        { "spot": "景点名称", "platform": "预约平台", "advance": "提前天数" }
      ]
    }
  ]
}
```

### 关键设计
- **引用自动映射**：行程内的 `spots`（景点名称数组）→ 自动匹配景点库 → 转换为 `spotIds`；`accommodation`（酒店名称）→ 自动匹配 → 转换为 `hotelId`
- **ID 生成规则**：`类型_时间戳_随机5位`（如 `spot_1782898995830_l3rg6`）
- **模板文件**：`data/import_template.json`（西安四日示例）

### 入口
- 设置页面 → 数据管理 → 「导入数据」按钮
- 支持拖拽上传和点击选择文件

## P3 · 待办清单页面

### 背景

当前购票平台和预约提醒只是"提醒清单"，没有状态管理。用户无法标记"已完成"。

### 设计原则

- **最小改动**：行程详情里的购票平台/预约提醒Tab结构保持不变，只追加状态字段
- **独立入口**：行程卡片加"待办清单"图标，点击进入独立清单页面
- **和预览页一致**：新开页面而非浮层，保持体验一致性

### 数据结构调整

**购票平台**：
```js

    name: "大同旅游景区直通车",
    uses: [
      { id: "u_xxx", desc: "大同古城↔云冈石窟", status: "pending" },  // 新增status
      { id: "u_xxx", desc: "大同古城→应县木塔", status: "booked" }
    ]
  }
]
```


## GitHub 身份验证方案

**现状**：当前使用 Personal Access Token 同步数据，存在 XSS/浏览器扩展/日志泄露等安全风险。

**短期方案（维持现状）**：
- 接受 Token 风险
- 提供安全提示（Token 最小权限、定期 revoke、不使用时要清空）
- 适合个人使用场景

**长期方案（多用户协作）**：
- **推荐**：Firebase Authentication + Cloud Functions
  - Firebase 处理 GitHub OAuth 登录
  - Cloud Functions 调用 GitHub API
  - 免费额度够个人使用
- **备选**：GitHub OAuth App + 自建后端（Cloudflare Workers）
- 前提准备：注册 Firebase 项目 或 Cloudflare 账号

| 5 | 性能问题 | 多处 | `array.find() + array.filter()` 的 O(n²) 组合，可改为 Map 索引<br>级联下拉每次切换都重新渲染所有选项，可缓存中间结果<br>列表渲染使用 innerHTML 拼接大量字符串，无虚拟化 |
| 6 | 缺少数据校验 | core.js / 导入逻辑 | `getLocationData()` 返回默认值时未验证结构完整性<br>导入数据时部分字段缺失未做防御性处理 |
| 7 | 配置硬编码 | 多处 | GitHub 分支名 `'main'`、`setTimeout(..., 20)` 等魔法数字散落各处<br>建议在 core.js 头部统一为 `const CONFIG = {}` |

### 🟢 低优先级（锦上添花）

| # | 问题 | 位置 | 说明 |
|---|------|------|------|
| 8 | 可访问性 | 全局 | 缺少 ARIA 标签、键盘导航支持<br>模态框无焦点陷阱 |
| 9 | 构建优化 | 全局 | 无 CSS/JS 压缩或打包<br>可考虑引入简单的构建脚本（如 gulp）做压缩 |
| 10 | 预览页性能 | preview.html | ~1500+ 行，可拆分为独立 JS/CSS |
